# B2 — геоид по умолчанию в lib_vertical (6.67)

**Задание:** AGENT_HANDOFF_2026-11.md §3-B2. Вариант «константа 15.9 под
именем EGM2008» заменён поточечным геоидом `geoid_egm2008.Geoid` и сделан
вариантом **по умолчанию**; `city_v3` (15.673/региональные) оставлен
только для воспроизведения старых результатов.

## Изменения

- `scripts/geoid_egm2008.py` — каноническое место модуля (копия из
  `handoff_2026-11/`); сетка `/tmp/my-project/data/us_nga_egm08_25.tif`
  (env `SPB_EGM2008_GRID` переопределяет).
- `scripts/lib_vertical.load_vertical(..., geoid_source='EGM2008')`:
  - режим `grid`: `H_bs77 = h_ell − N_EGM2008(lon, lat) − D`; D читается
    из `results/datum_6.61/datum_D.json` (B3: 0.00 ± 0.06, бюджет 0.10;
    env `SPB_DATUM_D_JSON` переопределяет); σ сдвига для `pixel_sigma` —
    бюджет 0.10 (`vert['sigma_m']`).
  - `shift_m = None` в grid-режиме **намеренно**: скалярного сдвига не
    существует (N по городу 15.764…16.004, разброс 0.240 м); старый код,
    арифметующий с `shift_m`, падает громко, а не молча считает на
    константе. Пересчёт — `ellipsoid_to_bs77(h_ell, lon, lat, vert)`.
  - молчаливый дефолт 15.9 удалён: без `city_calibration.json` city_v3
    падает; неизвестные `geoid_source` отвергаются.
- `city_v3` — прежнее поведение дословно (город 15.6727, σ 0.6286;
  vo/mainland берут региональные только при significant), с предупреждением
  о запрете в новом коде.

Переключение **продуктов** 6.x на grid-режим — при следующем пересчёте
якорей (инвентарь констант в `docs/datum_bs77_egm2008_6.61.md`);
скрипты v4-эпохи (04_*) продолжают работать только с city_v3-схемой —

`ellipsoid_to_bs77`.
