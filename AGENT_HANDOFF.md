# План для второго агента + аудит скриптов

## Контекст

Репозиторий: 36 файлов, 35 скриптов + README. Pipeline v4 (PMF + 4-tile Copernicus) 
даёт Passport MAD 1.55 м, ICESat holdout MAD 0.32 м. Модуль 13 (Невская губа) 
считает V(H), но три числа не сходятся — см. ниже.

## Три проблемы

### 1. Зеркало губы завышено на треть
```
расчёт 13_nevskaya_guba : 425.8 км² (первый прогон, широкий полигон)
пересчёт с узким полигоном: 330.3 км² (ближе к справочному 329)
справочная площадь губы : ~329 км²
```
Причина: `cop < 0.5` включает прибрежные низины, физически примыкающие к воде. 
`split_low_pixels` с требованием примыкания к заливу не используется.

### 2. Два расчёта губы расходятся на треть
```
13_nevskaya_guba : водных px 115 390 841 (первый прогон)
namyv_impact     : водных px  89 525 103 (узкий полигон)
разница          :  25 865 738 px = 95 км²

H=1.0 м: 445.8 против 331.7 млн м³  (+34%)
H=2.0 м: 903.7 против 665.1 млн м³  (+36%)
H=3.0 м: 1372.0 против 1000.0 млн м³ (+37%)
```
Узкий вариант (331.7 при H=1.0) ближе к справочной оценке (329).

### 3. ICESat holdout: MAD 0.316 при RMSE 3.072
Отношение 9.7 — подпись небольшой доли катастрофических промахов. 
Медиана −0.356 (модель систематически ниже лазера, согласуется с паспортом −0.234).

## Аудит: 8 дефектов в spb_full_run_v2.py

### Дефект 1 (главный): ICESat пишется в поверхность, а не в опору
```python
# строки 404-413
for p in ice_pts_in_block:
    surface[r_i, c_i] = h_ice       # ← точечная запись в ГОТОВУЮ поверхность
    detail[r_i, c_i] = 22
```
Лазер втыкается точечно после построения prior. Не участвует в диффузии.
Отсюда train MAD = 0.0 (значение записано как есть).

**Правильно:** точки лазера идут в `h_known` как опора ДО `build_prior`, 
с весом `1/σ²` при `σ = 0.10`. Тогда поле подтягивается вокруг них на десятки метров.

### Дефект 2: build_prior вызывается без весов
```python
prior = libg.build_prior(h_known, domain=domain, iters_per_level=30)
```
Вся взвешенная схема не работает: ни приоритет лазера, ни пониженный вес у воды.

### Дефект 3: масштаб огибающей зафиксирован
```python
libg.anchor_field(h_bs, building_mask, water_mask, pixel_m=PIXEL_M, block_px=60)
```
`block_px=60` отключает `choose_block_px`. Для города плотность открытой земли 
в центре и в Купчино разная — масштаб должен выбираться по данным.

### Дефект 4: дальнее поле не прижимается
`calibrate_cap` и `cap_far_field` не вызываются. На острове они убрали +1.51 м 
у класса «дальняя опора». Сейчас класс 23 даёт MAD 1.953 на 69% выборки.

### Дефект 5: приёмка без связности рельефа
Используется `accept_dsm`, а не `accept_dsm_with_relief`. Спуски к воде теряются: 
DSM там верен, гладкий prior — нет, и пиксель отбраковывается. Для губы это 
прибрежная полоса — ровно то, что важно.

### Дефект 6: намыв не помечается
`stale_dem_mask` не вызывается. Намыв определяется координатным прямоугольником 
`lon 30.10–30.30, lat 59.91–59.97`, куда Лахта не попадает (lat 59.98–60.01).

### Дефект 7: отметки ниже нуля зажимаются
```python
below = np.isfinite(surface) & (surface < 0) & (stat == 1)
surface[below] = 0.0
```
Прячет провалы вместо диагностики. Пиксель ниже нуля — сигнал ошибки, 
его надо считать, а не выравнивать.

### Дефект 8: маска воды
```python
water_extended = water_mask | (np.isfinite(cop) & (cop < 0.5))
```
Отсюда зеркало 425.8 км² против 329. `split_low_pixels` не используется.

## План работ (A-E), по приоритету

### Задача A. Интерактивная карта (конечный продукт)
- A1: Пирамида тайлов из spb_ground_surface_2m.tif (gdal2tiles / rio tiler)
- A2: Ползунок уровня (из vo_ground_flood_map.html)
- A3: Кайма честная — σ по detail, не общая
- A4: Слои — паспортные точки, маска воды, намывы, районы
- Приёмка: карта открывается, ползунок двигается, В.О. совпадает с прежней

### Задача B. Намывы по датам, а не по координатам
- B1: mindate/maxdate из провенанса мозаики
- B2: stale_dem_mask + проверка по высоте
- B3: Проверить: Морской фасад, Лахта, Горская, Сестрорецк, Канонерский
- B4: Пересчитать namyv_impact.json
- Приёмка: площадь намывов больше 21.68 км²; Лахта присутствует

### Задача C. Подключить машинерию целиком
По одному дефекту за прогон, с замером после каждого:

- C1: ICESat в опору ДО build_prior, с весом 1/σ² (σ=0.10)
      Ожидание: train MAD перестанет быть нулём, holdout улучшится
- C2: build_prior(weights=): лазер σ=0.10, DSM-опора σ=0.50, вода σ×3
- C3: choose_block_px вместо block_px=60
- C4: calibrate_cap + cap_far_field
      Ожидание: класс 23 подтянется
- C5: accept_dsm_with_relief вместо accept_dsm
      Проверка: три марки у Смоленки (1.03, 1.8, 1.7 м) улучшатся
- C6: Убрать surface[below]=0, вместо него счётчик в QA

Приёмка каждого шага: паспорт (median, MAD, %>2м) и ICESat holdout 
до и после, на одном множестве точек.

### Задача D. Маска воды
- D1: split_low_pixels с требованием примыкания к заливу
- D2: Критерий уклона берега (резкий = акватория, плавный = пойма)
- D3: Приёмка — зеркало ~330 км², два расчёта сходятся
- Блокирует расчёт по губе

### Задача E. Отчётность
- E1: Свести оба расчёта губы в один модуль
- E2: full_report.json: n_ground_lines, состав маски воды, 
      площадь в проекции и на земле, train/holdout раздельно
- E3: Прогонять тесты автоматически

## Порядок выполнения

```
1. A (карта)          конечный продукт, покажет проблемы наглядно
2. D (маска воды)     блокирует расчёт по губе
3. C1-C2 (лазер+веса) самый большой ожидаемый выигрыш
4. B (намывы)         закрывает Лахту
5. C3-C6              по одному, с замером
6. E                  сведение отчётности
```
