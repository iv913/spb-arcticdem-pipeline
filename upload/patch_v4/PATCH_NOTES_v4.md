## ОБЯЗАТЕЛЬНЫЙ порядок пересборки

Дефект №1 означает, что **старый кэш OSM управляет поведением конвейера**.
Пока он лежит на диске, фикс `water_margin_deg` не действует, маска воды
остаётся рваной, барьер диффузии в модуле 04 не работает, а пиксели Невы
попадают в поверхность как земля. Поэтому первая строка — не опциональна:

```bash
rm -f scripts/dem_cache/osm/owner_map_osm.json      # кэш эпохи до фикса воды
rm -f download/vo_surface.tif download/ground_surface.tif \
      download/vo_flood_surface.tif download/vo_ground_flood_surface.tif

python3 scripts/city_calibration.py       # -> version=v3, regional, MAD
python3 scripts/01_owner_map.py           # -> owner_map.tif (новый кэш OSM)
python3 scripts/multi_dem_profile.py
python3 scripts/02b_profile_fusion.py
python3 scripts/02_road_reconstruct.py    # -> road_surface.tif (Большой)
python3 scripts/03_flood_map.py           # -> flood_surface.tif + ползунок
python3 scripts/04_vo_pipeline.py         # -> vo_surface.tif (3 банда)
python3 scripts/04_ground_surface.py      # -> ground_surface.tif (4 банда)
python3 scripts/04b_ground_flood_map.py   # -> затопление по суше
python3 scripts/04c_compare_raw_filtered.py
```

## Что проверить после прогона

1. **Вода.** В логе `01`: не должно быть строки про игнорируемый кэш при
   втором запуске. В логе `04_ground_surface`: `owner=…` должно быть
   сопоставимо с `+компоненты ниже 0.3м БС=…`. Если компонент по высоте
   на порядок больше — Нева всё ещё не полигонизуется, и предупреждение
   об этом выводится явно.
2. **Площадь.** `ground_surface_qa.json` → `stat_area_km2`. Ожидание для
   Васильевского с островом Декабристов — **15–19 км²**. Было 25.9 км².
   Свыше 20 км² модуль сам пишет предупреждение.
3. **Компоненты суши.** `land_components_top10`: должна доминировать одна
   компонента со всем скелетом. Две крупные компоненты со скелетом —
   признак, что мост соединил остров с материком в маске, либо гейт 1
   всё ещё течёт.
4. **Скелет.** `skeleton.rejected`: сколько пикселей срезано по `source`
   и сколько по санитарному диапазону. Второе число должно быть близко к
   нулю после правки №2 — если велико, значит быстрый эстиматор всё ещё
   проваливается, и такие улицы идут в очередь на полный конвейер.
5. **Тираж.** В логе `01` для каждой улицы печатается список совпавших
   имён. Любой чужой объект теперь роняет прогон с явным сообщением, а не
   тихо подставляет геометрию Большого проспекта.
6. **Стек приоритетов.** Строка «Наложено: N px из road_surface.tif
   (перепроекция на сетку острова)». N должно совпадать с суммой
   `surface_px` из `road_qa.json`. Ноль — теперь ошибка, а не тишина.
7. **Проценты.** В `vo_flood_qa.json` и `vo_ground_flood_qa.json` появилось
   поле `denominator_px_land`. Проценты затопления **не сопоставимы** с
   прошлыми прогонами: раньше в знаменатель входила акватория.
8. **Вилка.** Пессимистичный сценарий станет уже (перелив теперь требует
   `Z + u < H`), оптимистичный не изменится. Если ядро схлопнулось в ноль
   на всех уровнях — это не баг, а честное следствие σ_привязки 0.80 м;
   лечится локальной калибровкой В.О., а не порогами.

## Синтетика

`test_patch_v4.py` — 31 проверка, работает без rasterio/GDAL
(`python3 test_patch_v4.py`). Покрывает: уникальность ключа кэша,
нормализацию имён улиц, вложенность и симметрию сценариев, монотонность
бюджета по классам, разделение водоёма и кромок, отсечение компоненты
без скелета, знаменатель, и выигрыш выборки по маске дороги.

Показательные числа из последнего теста — выборка пикета на линии В.О.
шириной 8 м, окно ±10 м:

| Сцена | сырой квадрат | по маске дороги |
|---|---|---|
| каньон, за домами дворы на 1.4 м ниже | −1.40 м | +0.00 м |
| улица у набережной, в окне акватория | −2.95 м | +0.00 м |
| Большой проспект (проезжая часть 45 м) | 0.00 м | 0.00 м |

Вторая строка объясняет наблюдавшиеся «дороги на −1.86 м БС» у набережных:
нижняя огибающая защищена только сверху (`UP_REJECT = +0.4` м), поэтому
всё, что в окне ниже проезжей части — двор, съезд, вода — утягивает
оценку вниз, и никакой порог этого не ловит. Третья строка — проверка,
что правка не трогает то, что уже работало на пилоте.

## Что НЕ входит в патч

- **Локальная калибровка В.О.** Бюджет по-прежнему упирается в
  σ_привязки: √(0.107² + 0.80² + …). Пока `between_street_mad_m` = 0.80,
  вилки останутся широкими независимо от качества формы. `lib_vertical`
  уже умеет брать `regional.vo`, но только если `significant` — то есть
  сначала нужен пересчёт `city_calibration.py` с дедупликацией коридоров.
- **Уравнивание сети по перекрёсткам.** Это следующий шаг, а не правка.
- **Драйвер тиража** (по-уличные окна, подкаталоги, сводный
  `streets_qa.csv`). После правки №2 быстрый эстиматор стал пригоден как
  скрининг, так что драйвер имеет смысл писать уже поверх этого патча.
