# 5.72 — Автотест приёмки планов по эталону земли (тиражирование правила 5.69)

Дата: 2026-10-05. Скрипт: `scripts/icesat_site_test_5.72.py` (v2).
Протокол самотеста: `results/icesat_site_selftest_5.72.json`.

## 1. Назначение

Правило 5.69 («site-level ICESat-тест») автоматизировано как обязательный шаг
приёмки любого нового плана в цикле тиражирования: до внесения отметок в
канон проверяется, что медиана отметок согласована с медианой ЗЕМЛИ в
радиусе площадки; разница >5 м → план в относительных/проектных отметках
или ошибка геопривязки → стоп и отрицательный протокол.

## 2. Уроки v1 → v2 (критический разбор)

- **v1 (только ICESat-2 в круге 500 м)**: (а) на Полюстровской гряде круг
  смешивает холм (27.5 м) и кампус → ложный REJECT; (б) в плотном центре
  треков нет (n=0) → INSUFFICIENT_GROUND.
- **v2**: эталон земли — **непрерывный FABDEM bare-earth** (5.71,
  MAD 0.344 на 33 908 полевых точках), окно 300 м, медиана; ICESat-2 clean
  — кросс-чек (печатается в протоколе). Пороги: |diff|≤3 → ACCEPT,
  3–5 → BORDERLINE (флаг site-level), >5 → REJECT_DATUM.
- **Запрет на выдуманные значения в самотесте**: первая прогонка v2 с
  тестовыми числами «12–15 м» дала ложный REJECT Политехнической (реальная
  медиана отметок там 29.81 м — площадка на гряде). Самотест переведён на
  реальные значения из канона archi_final_clean_v2.csv.

## 4. Новые следствия для канона

1. **ID Moskovskiy (33 отм.)** — теперь ДВА независимых количественных
   признака сомнительной геолокации: дублирование координат «Фрунзенской»
   (5.66) и расхождение отметок с FABDEM-землёй −3.64 (BORDERLINE, 5.72).
   Статус: остаётся в каноне с флагом site-level; приоритет перепроверки
   адреса/плана повышен (после этапа приёмки новых планов).
2. **Политехническая**: FABDEM-земля 27.75 ≈ ICESat 27.46; отметки 29.81 →
   +2.06 — площадка на Полюстровской гряде, отметки корректны. Отклонение
   +3.3 относительно M-CLF — недооценка модели на гряде (учесть при
   калибровке M-CLF на севере).
3. Кросс-чек DTM vs ICESat в протоколе позволяет ловить расхождения
   эталонов на площадке (Дунайский: 13.37 vs 14.30 — ±1 м в пределах
   точности обоих).

## 5. Использование в цикле тиражирования

```bash
python scripts/icesat_site_test_5.72.py --name "ЖК X" --lat 59.8 --lon 30.4 \
  --values 6.1,6.3,6.2 --radius 300 --out results/plan_XXXX_site_test.json
```

- ACCEPT → отметки вносятся в канон (обычный протокол ②);
- BORDERLINE → вносится с флагом site-level + фиксацией diff;
- REJECT_DATUM → стоп, отрицательный протокол (шаблон 5.69);
- NO_DTM_COVERAGE (вне сетки 5.71) → только ICESat-кросс-чек, решение вручную.
